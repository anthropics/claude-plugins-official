# Contract: the geometry estimate

**Emitted by** `rfq-to-quote`, at the design step (step 7), or typed by an
estimator by hand
**Consumed by** `quote-build`, at the hours step
**Chain** 1, RFQ to quote (steps 7 to 9)
**Contract version** 1

Rules that govern every contract are in [README.md](README.md).

---

## What this carries, and what it never carries

**The part as the plant would make it, read from the customer's drawing:** the
stock, the datums, every feature with the tolerance that drives it, the setups
and the operation list. It is what `quote-build` derives hours from when no
routing for this part and revision exists, and what it cross-checks a routing
against when one does.

**It carries no hours, no rates and no prices.** Hours are derived from it by
`quote-build` after Gate 3, because hours derived from a model nobody has
confirmed are a guess with a decimal point. A geometry estimate that grew an
hours column would let an unconfirmed model price a job.

**It is an internal estimating aid and never goes to a customer.** The model
it describes was generated by the plant to estimate from. It is not the
customer's design, it is not a proposal, and nothing in it is sent. That
includes `cost_down_proposals`: a cheaper way to make the part is an idea for
the estimator, not a change offered to the customer.

**It must be hand-authorable.** Where Fusion is not connected, an estimator
can type the feature list from the drawing into this shape, and the hours step
runs on it exactly as it would on a generated one. So every model-only field
may be null, and the required core is what a person reading a print can fill
in.

## Header

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `contract_version` | integer | Required | |
| `site` | string | Required | Rule 7 |
| `inquiry_ref` | string | Required | The intake form's `rfq_reference`, or the inquiry's own reference where the customer gave none |
| `line_no` | integer | Required | The intake form line this estimates. One estimate per line |
| `part_number` / `part_number_verbatim` | string or null | Degrades | Rule 3. Null on a new part with no number yet |
| `geometry_path` | enum | Required | `C2`, `C1`, `B`, `A`, `none`. Carried from the intake form's `geometry_path`, after any reclassification at `rfq-to-quote` step 7. See the path table below |
| `drawing_revision_priced_to` | string or null | Required | The revision every feature below was read from. Null only where there is no drawing: path A, where the estimate then supports a ROM only, and path C1, where each feature's `source_ref` names the STEP file |

### The paths

| Path | What it means | `origin` |
|---|---|---|
| `C2` | A drawing (PDF, image or text extract). The model is generated from the drawing's dimensions, tolerances and notes | `built_from_drawing`, or `hand_entered` |
| `C1` | A STEP or other 3D file, and no drawing. The file is imported and read; nothing is generated. **STEP import through the connector is unverified**, and so is reading the STEP as text without CAD. A C1 line with a drawing is C2 | `customer_step`, or `hand_entered` |
| `B` | A drawing plus a different prior part whose model on file is named as the starting point. The prior model is opened, the drawing's changes applied, and the result saved as a new document; **the prior model is never overwritten**. A new revision of the same part is C2. Where the prior model is unavailable the line falls back to C2 and the estimate says so | `adapted_from_prior` |
| `A` | Text specifications, no drawing. Built with the same calls as C2, every dimension and tolerance `from_text`. **The estimate supports a ROM only, never a firm quote** | `built_from_text`, or `hand_entered` |
| `none` | No geometry in the package — a repeat part named by number only | No estimate. Priced from its routing or actuals, or a question back to the customer |

## Model

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `origin` | enum | Required | `built_from_drawing`, `adapted_from_prior`, `customer_step`, `built_from_text`, `hand_entered`. Per the path table above. `geometry_path` is the path that actually ran: a path B line that fell back is `C2` and `built_from_drawing` |
| `document_ref` | string or null | Degrades | The new Fusion document the model lives in. Null on `hand_entered` |
| `base_model_ref` | string or null | Optional | The prior part's model and the version it was opened at, path B only. **Never overwritten** — the producer reads its version again after the run and stops if it moved. Null on every other path, including a path B line that fell back to C2 |
| `cad_backend` | enum | Required | `fusion` or `none`. `none` on `hand_entered`, and on `customer_step` when the STEP was read as text without CAD |
| `generated_at` | timestamp with zone or null | Degrades | Rule 4. Null on `hand_entered` |
| `document_integrity` | object | Required | See below |
| `model_checks` | object or null | Degrades | Bounding box and volume read back from the model, and the hand calculation they were checked against, each with its unit |

### `document_integrity`

The Fusion connector can replay an earlier script into every later call until
Fusion restarts, which puts geometry nobody asked for into the document. So
the bodies and sketches are listed before and after every design step, and the
result travels with the estimate.

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `result` | enum | Required | `clean`, `foreign_geometry`, `not_checked`, `not_applicable`. `not_applicable` only where no CAD document was opened: `hand_entered`, or a STEP read as text |
| `bodies_before` / `bodies_after` | list of strings or null | Degrades | Names as Fusion listed them |
| `sketches_before` / `sketches_after` | list of strings or null | Degrades | |
| `checked_at` | timestamp with zone or null | Degrades | Rule 4 |
| `detail` | string or null | Required when `result` is not `clean` | What was found, or why it could not be checked |

**An estimate with `foreign_geometry` is not emitted as a usable estimate.**
The step failed; the estimate exists only to say so.

## Stock

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `material` | string | Required | As the drawing states it, with `source_ref` |
| `form` | string or null | Degrades | Bar, plate, round, casting. As the drawing or the material spec states it |
| `size` | string or null | Degrades | With units |
| `fit_check` | object or null | Degrades | `part_envelope`, `cleanup_allowance` (with unit and where it came from), `fits` (boolean), `flag` (string or null — what does not fit, or what fits only without cleanup) |
| `source_ref` | string | Required | |

## Datums

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `datums` | list of objects | Degrades | Each: `label` (A, B, C), `feature`, `basis`, `source_ref` |
| `datums[].basis` | enum | Required | `stated` — the drawing identifies the datum feature. `inferred` — assigned from the dimension scheme because the drawing references the datum without identifying its feature. **Every `inferred` datum is shown at Gate 3** |

## Features

One row per feature or patterned feature set.

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `type` | string | Required | Face, pocket, through-bore, hole pattern, fillet, chamfer, slot, thread |
| `count` | integer | Required | |
| `dimension` | string | Required | With units, as read |
| `tolerance` | string or null | Degrades | As read. Null only where the drawing gives none and no general note applies, and then it is on `unreadables` |
| `tolerance_driver` | boolean | Required | True where this tolerance, not the geometry, decides the process — a reamed bore, a KC, a flatness callout |
| `surface_finish` | string or null | Degrades | As read |
| `reading_basis` | enum | Required | `printed_callout`, `general_note`, `from_text`, `unreadable_flagged` — the same vocabulary as the intake form. **A general-note tolerance applied to a feature is reading, and cites the note**; anything else is not a tolerance at all. Path A rows are all `from_text`. A path C1 row read from a STEP file has no tolerance to read: `tolerance` null, `unreadable_flagged`, and on `unreadables` |
| `source_ref` | string | Required | View and zone, or the note number. A feature with no `source_ref` is not permitted |

## Setups and operations

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `setups` | list of objects | Degrades | Each: `setup_seq`, `faces` (which faces are reached), `fixture_note`, `machine_class` (a class from `### Machining data` in the Plant context, or the class as named when that section is absent) |
| `operations` | list of objects | Required | Each: `op_seq`, `description`, `machine_class`, `setup_seq` (null for an operation off the machine), `features` (which feature rows it cuts), `outside_process` (boolean), `assumptions` (list of strings), `source_ref` |

The operation list is the plant's proposed way to make the part. **It is
confirmed at Gate 3 and only then derived into hours.**

## Tolerances, unreadables and questions

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `tolerances` | list of objects | Required | Every tolerance read: `characteristic`, `value`, `reading_basis`, `source_ref`, `key_characteristic` (the drawing's KC label or null) |
| `unreadables` | list of objects | Required, may be empty | Each: what could not be read, where, and why it matters. An empty list means everything was read, and says so |
| `questions_for_estimator` | list of strings | Required, may be empty | Inferred datums, assumptions in the operation list, anything the estimator must rule on at Gate 3 |
| `cost_down_proposals` | list of objects | Optional | Each: `idea`, `why`, `what_it_would_change`. **Internal only.** Never on the customer quote and never offered to the customer: proposing a design change back is a different workflow with its own gate, and it is not built |

## Approval

| Field | Type | Behavior | Notes |
|---|---|---|---|
| `approval.status` | enum | Required | `draft`, `confirmed`, `declined`. **The skill emits `draft`, always.** Only the estimator moves it, at Gate 3 |
| `approval.by` | string or null | Required when not `draft` | The estimator who ruled |
| `approval.at` | timestamp with zone or null | Required when not `draft` | Rule 4 |
| `approval.note` | string or null | Optional | What the estimator changed or ruled on — a corrected datum, a removed operation |

Per rule 8, a consumer reads this state rather than inferring approval from
context. The skill that built the model never marks it confirmed.

Only the fields that differ from the example above.

## Missing behavior for the consumer

| Situation | What `quote-build` does |
|---|---|
| No geometry estimate for a line with no current-revision routing | Degrades. The ladder starts at closed-job actuals if they exist, else first principles (rung 4), labelled. The internal sheet says the design step did not run and why |
| `approval.status` is `draft` | **Blocks rung 3 for that line.** Hours derived from an unconfirmed model do not reach a quote unless the estimator says so in the run; then the internal sheet records who said so and that the model was unconfirmed |
| `approval.status` is `declined` | Blocks rung 3 for that line. The ladder runs without it |
| `document_integrity.result` is `foreign_geometry` | **Blocks.** The design step failed. No hours are derived from this model |
| `document_integrity.result` is `not_checked` | Degrades. Hours may be derived after Gate 3, and the internal sheet says the integrity check did not run |
| `drawing_revision_priced_to` differs from the intake form line's `revision` | **Blocks.** The estimate was built to another revision. Return to `rfq-to-quote` step 7 |
| `geometry_path` is `A`, or `origin` is `built_from_text` | Degrades. **A ROM, never a firm quote**, labelled ROM on the internal sheet and called a budgetary estimate on the customer document, which says nothing about how it was estimated. A Gate 3 yes or an override does not make it firm |
| `origin` is `customer_step` | Proceeds after Gate 3. The internal sheet says the STEP import, or the text read of it, is unverified |
| `origin` is `adapted_from_prior` with `base_model_ref` null | **Blocks rung 3 for that line.** An adapted model that does not say what it was adapted from cannot be checked |
| A `datums[].basis` is `inferred` and `approval.status` is `confirmed` | Proceeds. The estimator ruled on it at Gate 3 |
| A feature has no `source_ref` | Blocks that feature. An unsourced feature is an inference |
| `cost_down_proposals` is present | Internal sheet only. **Never inside the customer quote**, in any wording |
| `model_checks` is null | Degrades. Say the model was not checked against a hand calculation |
