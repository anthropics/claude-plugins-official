# The Operations Command Center — what each panel holds

Loaded at step 3. The mechanism (finding the dashboard, the tool calls, the
fallback) is `../../../shared/live-dashboard.md`. This file is only the page.
House style is `../../../shared/artifact-style.md`; components named below are
defined there.

**The page is static.** Every number is computed in code during the run and
written into the HTML. The page never reads the database when someone opens
it, so it works for anyone it is shared with and the figures block covers
every number on it.

## Panel 1 — Today

In this order, the same order as the morning report in
`../../daily-production-report/SKILL.md`; the dashboard is where it now lives.

1. **Safety-flagged diagnosis records**, when any, above everything else,
   the freshness banner included.
2. **"Blocked — safety status unknown"**, when any: each record held out of
   both rankings, the totals and the pricing, with its asset, start time and
   the reason.
3. **Freshness banner.** Directly under any safety block, and first when
   there is none; never a footnote. A missing or stale export is the banner's
   first row, with a `--critical` or `--warn` pill. A day stored
   `data_complete: false` says so here in one sentence: *"Downtime export did
   not land. Availability, OEE and downtime are not computed for Aug 31."*
4. **Today's actions**: issue, impact, next step, owner role, and whether
   it is a decision (waiting on an approval), an investigation or an
   observation, per step 4 of the report order. *"No decisions waiting
   today"* when none is.
5. **Output against plan**, by line, cell and product, with variances.
   Provisional rows marked, with the proposed normalizations listed.
6. **OEE** per asset or line, three components in separate columns, and the
   quality-convention line under the table.
7. **Downtime**, ranked by minutes and by frequency, both. The `Other` share
   stated as its own finding, never ranked.
8. **Priced losses**, with the rate source named and every unpriced quantity
   listed with its reason.
9. **Exceptions**, each with its commitment impact, and one traced reschedule
   move per significant exception, drafted, never applied.
10. **Data problems**, a numbered table with its count: classes 1 to 5 and 8
   only, two or three example rows per finding.
11. **"Checked, nothing wrong"**, after the table, outside its count: Class 6
    records, one line each.

## Panel 2 — Trend

Drawn from the `pulse_days` records, never from a prior page.

**Series, each over the last 14 and the last 30 production days:**

- OEE, and availability, performance and quality as separate lines
- Output against plan, one series per unit of measure, never summed across
  units
- Downtime minutes, ranked records only

**Charts are inline SVG built in code**, with the numbers baked in, using the
house tokens: `--accent` for the measured series, `--line` for gridlines,
`--warn` for a partial day's marker. A table under each chart lists the same
values, because a chart cannot be checked against the figures block and a
table can.

**A gap is drawn as a gap.** A day with no record, a record with
`data_complete: false`, or a null metric breaks the line there. It is never
plotted as zero and never interpolated across. The table cell reads *not
computed* or *no run for this day*, with the reason from the record's `gaps`.

**Week-over-week movers.** The seven production days ending on the report day
against the seven before, from `data_complete` records only, for all four:
output against plan, OEE by component, downtime minutes and scrap dollars.
Each mover names the metric, last week's value, this week's and the change,
and says how many days of seven each side rests on (*"5 of 7 days"*). When
the earlier window has no complete record, skip the section and say why.

**No stored history yet**, and nothing to back-fill: the panel says *"First
run: no stored history yet. The trend starts with tomorrow's run."* and holds
no empty chart.

**On a fallback run** the trend cannot read stored records. Where the exports
themselves cover earlier days, the panel may be built from them in this run,
labelled *"from this run's exports, not stored history"*; otherwise it says
the trend is unavailable because the dashboard could not be read.
